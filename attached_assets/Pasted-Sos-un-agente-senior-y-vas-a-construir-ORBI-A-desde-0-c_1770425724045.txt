1) Reglas NO negociables

NO usar mocks. Todo debe tener persistencia real en MySQL y endpoints funcionales.

Multi-tenant obligatorio: cada request del panel de clientes debe estar atado a tenant_id.

Flujos de auth separados:

SUPER ADMIN (Dueño Orbia) entra por endpoint protegido exclusivo.

Tenant Admin/Staff entra por login tenant.

Cliente final NO se loguea: solo tracking público temporal.

Seguridad:

JWT con claims (tenant_id, role, user_id, opcional branch_id).

Validación de pertenencia (ownership) en cada comando/handler.

Enlaces públicos firmados con expiración y scope limitado.

Tecnologías:

Backend principal: Node.js + MySQL.

Arquitectura: estilo DDD/CQRS (commands/queries separados, con validaciones fuertes).

Microservicio IA: Python (FastAPI) con STT real.

Configurable por tenant: estados, gastos, expiración de links, campos, módulos visibles, etc.

Control por plan: cada plan habilita módulos/limits. Debe existir middleware requireFeature("X") y enforceLimit("Y").

4) IA — STT real como microservicio Python (sin depender del navegador)

Implementar un microservicio Python FastAPI con STT real.
No usar WebSpeech API. No mocks.

4.1 Microservicio ai-service/

FastAPI + endpoint POST /stt/transcribe

Recibe audio (multipart) + language + context (orders/cash/products) + tenant_id + user_id (firmado desde backend)

Devuelve JSON:

transcript (texto)

confidence (si el modelo lo permite)

intent (clasificación simple)

structured_command (ej: create_order / add_cash_movement / create_product)

extracted_fields (monto, cliente, fecha, items, etc.)

Usar un modelo real:

Preferido: faster-whisper (más rápido) o whisper.

Si el entorno no soporta GPU: correr CPU y optimizar (small/base).

Registrar todo en MySQL en stt_logs (sin datos sensibles de audio guardado por defecto; guardar metadata y transcript).

4.2 Flujo correcto (sin inventar)

Frontend graba audio (WebRTC MediaRecorder) y lo manda al backend Node.

Backend Node valida auth/tenant/feature flag STT.

Backend Node reenvía el audio al ai-service (interno) con tenant_id/user_id.

ai-service transcribe y devuelve comando estructurado.

Backend Node ejecuta el command real (crear pedido / movimiento / producto) y responde.

Importante: el microservicio IA NO toca directamente la DB del dominio para no romper arquitectura; solo devuelve transcripción + parsing.
